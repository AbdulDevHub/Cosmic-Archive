## Scene system and hero galaxy (F3a, 2026-11-16)

| ID | Decision | Reason | Alternatives rejected |
|---|---|---|---|
| D-034 | **Scene dependencies:** `three` 0.187 (the version the prototype ran), `@react-three/fiber` 9.8, `@types/three` (dev). Ink lines use three's own `Line2` addon. No drei, no postprocessing. | D-014 chose three with R3F; the prototype needed nothing else, and `Line2` already draws constant-width screen-space lines. | drei (most of it unused); a hand-written line shader (more code for the same result). |
| D-035 | **The host uses R3F's `createRoot`, not `<Canvas>`,** and scenes add their objects as `<primitive>`. | `<Canvas>` registers every three class, which defeats tree-shaking; this keeps host + three + R3F at 185 KB gzip against the 220 KB budget. | `<Canvas>` with JSX three elements. |
| D-036 | **Posters are WebP, two per scene** (`wide` and `narrow`), chosen by aspect ratio with `<picture>`; `SceneSlot` takes `posters={{ wide, narrow }}`. Changes the single `.avif` in the F3a brief and in `ARCHITECTURE.md` 3.1. | The phone composition is a different picture, not a crop. `npm run posters` saves the scene's own canvas from headless Chromium, which encodes WebP but not AVIF, so no image dependency is needed. | One poster cropped with `object-fit` (wrong composition on phones); adding `sharp` for AVIF. |
| D-037 | **The page background is on `html` only;** `body` is transparent. | The poster and canvas sit behind the page at a negative z-index, and a background on `body` paints over them. | A positive z-index for the scene with every page section lifted above it. |
| D-038 | **The governor counts a run of very long frames as slow.** One gap over 250 ms is still ignored (tab switch, rebuild); consecutive ones are counted at 250 ms each. The ladder has five rungs: high, medium, medium at low pixels, low, low with half the glow, then `static`. | As first written, a device slower than 4 fps never stepped down, because every frame was thrown away as a hitch. Found by the throttling test. | Ignoring all long gaps. |
| D-039 | **`npm run fallbacks`** runs the fallback tests of `ARCHITECTURE.md` section 8 against the production build (Playwright, already a dev dependency). `shots`, `posters` and `fallbacks` share `scripts/lib/serve.mjs` and launch Chromium with software WebGL allowed. | "Tested, not assumed" has to be repeatable by the next session. | Testing by hand each session. |
| D-040 | **Dust leaves the canvas alpha alone** (separate alpha blend: zero, one). | With the colour factors applied to alpha, the dust lanes punched transparent holes into the saved posters. | Flattening the poster onto `--space` after the fact. |
| D-041 | **On wide screens the lower tiers are brightened to stay as full as `high`.** The glow layers (body, haze) carry the light of the sprites that were dropped; dust goes part of the way; disc points are 0.8 on `medium` and 1.4 on `low` against 0.52 on `high`. The governor's last step (half the glow sprites) doubles the strength of those left. The phone composition keeps the prototype's phone strengths. | At the first values `low` on a desktop looked thin beside the poster it fades in over, and the owner asked for a galaxy that is big and full. `ARCHITECTURE.md` 3.4 expected this. | Leaving `low` thin; raising the particle budgets. |
| D-042 | **A page that asks for a scene again gets a fresh scene** (the scene tree is keyed by the request, not the scene id), and `<html data-scene>` is cleared when the page leaves. | Going to another page and back inside the 300 ms fade reused the old scene, which never reported a first frame for the new request, so the canvas stayed hidden. Found in review; covered by the navigation test in `npm run fallbacks`. | Reusing the mounted scene and marking it ready by hand. |
